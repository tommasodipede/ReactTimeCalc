# BMI160 Threshold Calibration Tool 

## Overview 📖
This code is a standalone utility designed to run on the ESP32 before deploying the main Reaction Time system. Its sole purpose is to measure the physical forces applied to the starting blocks and determine the optimal `ENERGY_THRESHOLD` required for the main race firmware.

Since every starting block, track surface, and sensor mounting method is different, you cannot rely on a hardcoded threshold. This tool visualizes the exact energy output of an athlete's push-off in real-time.

## How It Works ⚙️
1.  **Gravity Calibration (Zeroing):** On startup, the system reads 200 samples of ambient gravity and vibration to establish a baseline (`base_x`, `base_y`, `base_z`).
2.  **High-Frequency Polling:** The ESP32 polls the BMI160 at 1600Hz via SPI, subtracting the baseline from every reading.
3.  **3D Energy Calculation:** It calculates the total kinetic energy applied to the sensor across all 3 axes using the formula: $E = \Delta x^2 + \Delta y^2 + \Delta z^2$.
4.  **Peak Hold:** The OLED display shows the absolute maximum energy peak reached during a movement.
5.  **Auto-Reset:** The peak value is held on the screen for 5 seconds to allow the user to read it, then automatically resets to 0 for the next test without needing a hardware reboot.

## Calibration Procedure 🛠️

### 1. Setup 🔌
* Flash this code to the ESP32.
* Mount the electronics to the starting block exactly as they will be during a real race.

### 2. Boot & Zeroing 🔋
* Power on the system. The screen will display **"DO NOT TOUCH!"**.
* Step away from the block so vibrations do not interfere with the gravity calibration.
* Wait for the screen to display **"READY!"**.

### 3. Testing 👟💨
* Have an athlete perform a standard sprint start off the block.
* Look at the OLED screen. The **"MAX PEAK"** value represents the maximum energy registered during that specific push-off. 
*(Note: The value on the screen is divided by 1000 to fit on the display).*

### 4. Setting the Main Threshold 🎯
* Perform 5 to 10 test starts and note down the "MAX PEAK" values.
* Find the *lowest* peak value generated by a legitimate start.
* Set your `ENERGY_THRESHOLD` in the main race firmware to about **60-70%** of that lowest legitimate peak. 
  
💡 **Example:** 
If your test starts output values around `1200 k`, `1450 k`, and `1100 k`, your lowest valid start is `1100 k` (which is actually `1,100,000` in raw units). You should set the `ENERGY_THRESHOLD` in the main code to around `750000`. This ensures all real starts are detected, while background noise (like someone walking near the block) is ignored.
